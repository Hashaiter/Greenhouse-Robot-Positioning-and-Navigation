# STM32 接线与运行

以下为 2026 年 10 月 24 日已经用于实物测试的接线。控制板为 STM32F103 系列，绿色板为 TB6612 电机驱动板，USB 转串口使用 CP210x。当前实车 A 对应右轮，B 对应左轮。

## 电机控制与编码器

| 绿色驱动板信号 | STM32 引脚 |
| --- | --- |
| PWMA | PA0 即 A0 |
| AIN2 | PA1 即 A1 |
| AIN1 | PA2 即 A2 |
| PWMB | PB12 即 B12 |
| BIN2 | PB13 即 B13 |
| BIN1 | PB14 即 B14 |
| STBY | PB15 即 B15 |
| E1A | PB6 |
| E1B | PB7 |
| E2A | PA15 |
| E2B | PB3 |

STBY 目前由 PB15 控制，不沿用早期直接接 3.3V 的连接。方向修正已在固件中完成，不需要为了该修正再交换现有电机线。

## 串口

| CP210x 模块 | STM32 引脚 |
| --- | --- |
| TXD | PA10 即 A10，STM32 接收 |
| RXD | PA9 即 A9，STM32 发送 |
| GND | GND 共地 |
| 5V 与 3V3 | 均不接 |

参数为 **115200、8N1、无流控、3.3V TTL**。当前电脑的端口为 COM5，端口号与电脑有关。ST-Link 用于 SWD 下载和调试，串口通信使用 CP210x；两者用途不同。同一时刻只有一个程序占用串口。

## 供电和下载

测试时采用绿色板上已经确认的稳压 5V 给 STM32 的 5V 引脚供电，GND 共地。该 5V 连接位于驱动板的其他位置，不能仅凭 Output_IO 的某个 5V 针脚空置判断是否供电。蓝色端子上标注的 Vout+ 不是这套接线中的 STM32 5V 电源点。

采用这一供电方式时，ST-Link 的 3V3 线保持断开，SWDIO、SWCLK 和 GND 可保留。改线时完全断电；烧录、复位或暂停 CPU 前，先物理拔下两个白色电机插头。

正常运行时先让 STM32 供电并启动，再连接 USB 转串口。结束后先拔 USB 转串口，再关闭小车电源，避免串口信号向未供电的 MCU 反向供电。

## 电脑端示例

在本工程根目录运行：

```powershell
python -m pip install -r requirements.txt
python tools/motion_link.py
```

不带 `--port` 时只打印示例，不访问串口。`tools/motion_link.py` 使用 pyserial，依赖版本记录在 `requirements.txt` 中。

目前完成的动作测试均为两轮架空、车体稳定、线材远离转轮的短时测试。下面的命令会实际转动电机，仅适用于已核对接线和供电的架空测试：

```powershell
python tools/motion_link.py --port COM5 --a 20 --b 20 --seconds 4 --confirm-wheels-lifted
```

`a` 是右轮，`b` 是左轮，单位为占空比百分比整数。工具会先发 STOP，约每 100 毫秒续发运动指令，结束时尝试再发 STOP；支持的动作时间大于 0 且不超过 10 秒。它是串口联调示例，尚不是 ROS 节点或完整上位机控制器。

不转电机时可先发送 `STATUS*14` 加真实换行查询状态。正常待机为 `state=0`，目标和施加占空比均为 0；静止时计数变化率与 RPM 归零，累计计数可以保留非零值。

STOP 禁用驱动并滑行，不代表机械制动、锁轮或实体急停。电流匹配、温升和带载条件尚未验证；目前的测试结果不能作为直接落地或长期运行的依据。

## 维护工具

`tools/chassis_debug.ps1` 是开发中使用的 ST-Link 状态工具，含原电脑的 STM32CubeProgrammer 路径，并默认读取匹配的 `Debug/GreenhouseCar_Forward.map`。跨电脑使用需要调整路径和匹配构建结果。正常电脑通信以串口工具为入口。
